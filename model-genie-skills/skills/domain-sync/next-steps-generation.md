# Generating NEXT_STEPS.md and ARCHITECTURE.md

Both are **derived, project-root** docs owned by domain-sync. Never hand-maintain them —
regenerate from the sources of truth so they can't drift.

---

## Standardized Gap-Status Enum (shared contract)

`NEXT_STEPS.md`, `_gap_registry`, the dashboard, and Genie caveats MUST all use one vocabulary.
The first pass used `Open`/`Descoped`/`Backlog` in `gap_analysis.md` but `OPEN`/`IN_PROGRESS`
in the registry/dashboard filter — so deferred rows silently vanished from the tools meant to
surface them. Standardize on:

| Status | Meaning | Surfaces in NEXT_STEPS? | Surfaces as Genie caveat? |
| --- | --- | --- | --- |
| `OPEN` | Not started, on the critical path | Yes (priority-ordered) | Yes |
| `IN_PROGRESS` | Actively being unblocked | Yes | Yes |
| `DEFERRED` | Real gap, consciously postponed (was "Descoped"/"Backlog") | Yes (in a Deferred section) | Yes |
| `ACCEPTED` | Known limitation, will not fix (accepted exception) | No (listed as accepted) | Yes (as a caveat) |
| `RESOLVED` | Closed | No | No |

**Migration rule:** map legacy `Open`→`OPEN`, `Descoped`→`DEFERRED`, `Backlog`→`DEFERRED`.
Dashboard/Genie filters that read `Status IN ('OPEN','IN_PROGRESS')` must be widened to include
`DEFERRED` so postponed work stays visible. This enum is the single source; `gap_analysis.md`
and `_gap_registry` seeding both adopt it.

## NEXT_STEPS.md — generation

Generate from three inputs, in this order:

1. **`_gap_registry`** (or `gap_analysis.md` if the registry isn't seeded yet) — every
   `OPEN`/`IN_PROGRESS`/`DEFERRED` row, priority-ordered (P0 → P3), with its `Unblock_Action`
   and `Assigned_To`.
2. **Open validation findings** — anything the validation suite flags that isn't a data gap:
   missing drift baselines, facts lacking INTEGRATION cells, a table below Grade B.
3. **Prod-promotion checklist** — from `progress.md` "Next Action" (unpause → N clean runs →
   promote → wire downstream).

### Template

```markdown
# {Domain} — Next Steps

<!-- synced-against: progress.md @ {date} (rev: {sha/run id}) -->
*Generated by domain-sync from _gap_registry + validation findings + progress.md. Do not hand-edit.*

## Do next (critical path)
1. **[P0] {gap}** — {Unblock_Action} — owner: {who} — unblocks: {entities}
2. ...

## Validation follow-ups
- {e.g. "3 facts missing INTEGRATION cells: fact_x, fact_y, fact_z — re-run validation batch"}
- {e.g. "drift baselines not captured — run baseline pass"}

## Prod promotion checklist
- [ ] Unpause schedule; confirm {N} consecutive clean runs
- [ ] Deploy to {prod catalog}.{schema}
- [ ] Wire downstream gold/dashboard consumers

## Deferred (postponed, still tracked)
- **[P2] {gap}** — {why deferred} — revisit when {condition}

## Accepted limitations (will not fix)
- {gap} — {reason} — surfaced as Genie caveat
```

Point every station SKILL.md onboarding path (and `ARCHITECTURE.md`) at `NEXT_STEPS.md` as the
canonical "what do I do now" artifact.

## ARCHITECTURE.md — the steady-state map

A returning agent (or human) reads this FIRST to understand how the codebase fits together and
how to keep it in sync. Regenerate when structure changes (entity added, layer added, skill
added); otherwise it's stable.

### Template

```markdown
# {Domain} Model — Architecture & Sync Guide

<!-- synced-against: progress.md @ {date} -->

## What this model is
{1-2 lines: domain, layer(s), source systems, who consumes it}

## The medallion / layering
{bronze sources → silver dims/facts → gold marts/metrics. Load-order tiers.}

## Source-of-truth hierarchy
{copy the ranked table from domain-sync/SKILL.md — progress.md + _gap_registry are rank 1}

## Artifact map (who owns what)
{link to ARCHITECTURE.md for folder ownership; summarize the derived-doc web}

## How to make a change without breaking sync
1. Fix the source of truth (MERGE/DDL/progress.md/_gap_registry)
2. Load the `domain-sync` skill — "I changed X, keep everything in sync"
3. It scopes regeneration to the changed entity, re-stamps, and re-lints
> Never hand-patch a derived doc to hide a contradiction — fix the source and regenerate.

## Key conventions
{link to conventions.yml / naming-standards.md — catalog map, naming, load-strategy thresholds}

## Where to look
- What to do next → `NEXT_STEPS.md`
- Current health/grades → validation dashboard + Model Guide health cell
- What was built & why → `docs/explanation/domain_narrative.md`
- Known gaps → `_gap_registry` (enum: OPEN/IN_PROGRESS/DEFERRED/ACCEPTED/RESOLVED)
```

### Exit gate
`ARCHITECTURE.md` and `NEXT_STEPS.md` both stamped current; linter clean. Report and finish.
