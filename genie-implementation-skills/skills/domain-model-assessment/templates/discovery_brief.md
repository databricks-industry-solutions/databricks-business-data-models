## 1. What a "vibe model" is and why it exists

The **vibe model** is a Silver-layer business semantic model — the governed, conformed layer
that sits between raw ingested data and analytics:

> **How this model was created, and how we treat it here.** The model was generated by an AI
> ensemble (~251 rules), iteratively refined and versioned per the vibe-modeling blog. In
> **this** motion, though, we treat it as a **one-shot / pre-iterated frozen input** and edit it
> **only via Genie Code** (scoped SQL against the `vibe_metamodel_*` tables) — **no model-agent
> regeneration**. So Genie should treat the metamodel as **revisable in place, not sacred**:
> when profiled data contradicts or exceeds the model, call it out. Structural misses become
> **vibe-model prompts** the user takes to the vibe agent to iterate upstream; small
> additive/corrective changes are made in place via Genie Code.

```
source systems  →  Lakeflow Connect / ingestion  →  BRONZE (raw)
                                                        │
                                                        ▼
                              ┌──────────────────────────────────────┐
                              │  VIBE MODEL  (this — Silver semantic) │
                              └──────────────────────────────────────┘
                                                        │
                                       populate via SDP / Jobs
                                                        ▼
                                   GOLD / metric views  →  Genie / AI-BI / dashboards
```

## 5. Genie's discovery task

**Goal:** produce a **source-to-target mapping report** proposing, for each of the
{N} real tables, which lake data can populate it. **Discover and propose only.**

For each target table (in load order):
1. Restate the intent in one line from `vibe_metamodel_product.description`
2. Find candidate sources (bronze + existing silver/gold). Report each as `catalog.schema.table`
3. Map columns: for each target column, name the best source column and transformation.
   Honor `value_regex` and `dbx_business_glossary_term`. Flag columns with no source.
4. Resolve keys & FKs: propose PK derivation (deterministic hash) and FK resolution
5. Grade the fit: Full / Partial / Blocked with reason
6. Gaps & asks: list tables/columns with no viable source and what ingestion would unblock them

**Rules:**
- Read-only against **data** — no CREATE/INSERT/MERGE/COPY into any bronze/silver/gold data
  table. The one permitted write is a scoped **metamodel edit via Genie Code** (`vibe_metamodel_*`
  tables), and only at the Phase 2C / Step 2.7 human gate when the user picks edit-in-place — see
  the `domain-model-assessment` skill, Rule 2. No model-agent regeneration.
- Before mapping, run the Phase 1 metamodel inspection queries.
- Prefer prod/bronze sources already readable over dev; note which catalog each is in.
- Where a target column maps only via a join, state the join.
- Keep `{universal_identifier}` central — most facts hang off it.
